## Хранение данных: PostgreSQL и драйвер psycopg 3

Четвертое занятие Темы 4 «Разработка веб-приложений» курса «Искусственный интеллект» для 9 класса. Программный интерфейс сервиса «Покрытие» из Т4.Б1.3 хранил поездки в словаре внутри процесса Python, и они пропадали при каждом перезапуске сервера. Теперь каждый ученик запускает свой сервер базы данных PostgreSQL 18, повторяет SQL на архиве из 40 поездок беспилотных автомобилей, описывает таблицу поездок в `schema.sql` и переводит программный интерфейс на базу данных через драйвер psycopg 3. Адреса и ответы программного интерфейса не меняются: клиенты не замечают переезда. Задания проверяются тестами `pytest`. Занятие открывает практическую работу №2 по программе.

## Теория (презентация и ноутбук)

1. **PostgreSQL как сервер.** Почему данные нельзя держать в словаре: перезапуск, несколько процессов, объем и поиск. Чем PostgreSQL отличается от SQLite: отдельная программа-сервер, подключение по сети с паролем, строгие типы, роли. Два варианта запуска: архив без установки и контейнер Docker. Строка подключения в файле `.env`, который не попадает в Git. Консоль psql и ее служебные команды.
2. **Схема и SQL.** Типы `integer`, `numeric`, `text`, `date`, `timestamptz`; номер строки от базы `GENERATED ALWAYS AS IDENTITY`; ограничения `PRIMARY KEY`, `NOT NULL`, `DEFAULT`. Почему пробег хранится в `numeric`, а не в `double precision`. Повторение SQL: отбор, сортировка, агрегаты, группировка, `HAVING`, `COUNT(*) FILTER`. Команда `RETURNING`.
3. **psycopg и FastAPI.** Соединение, выполнение запроса, строки-словари `dict_row`, перевод типов. Транзакции: когда изменения подтверждаются (`COMMIT`) и отменяются (`ROLLBACK`). Знаки подстановки `%s` и `%(имя)s` и почему нельзя склеивать запрос f-строкой. Зависимость `get_conn` с `yield` и параметр `scope="function"`. Тестовая база и подмена зависимости в тестах.
4. **Практика.** План из шести заданий, первый запуск, проверка командой `pytest`.

## Практическая работа

| Задание | Что пишем | Главный результат |
| --- | --- | --- |
| З1 | сервер PostgreSQL, роль, базы, `.env` | приложение подключается к рабочей и тестовой базе, `/api/health` показывает версию сервера, `.env` не попадает в Git |
| З2 | `sql/q01.sql`–`q10.sql` | десять запросов к архиву поездок: отбор, сортировка, группировка, `HAVING`, `FILTER`, `UPDATE` и `DELETE` с `RETURNING` |
| З3 | `schema.sql`, `app/init_db.py` | таблица `trips` с нужными типами, номером `IDENTITY` и значениями по умолчанию; повторный запуск не теряет данные |
| З4 | `app/db.py` | зависимость `get_conn`: соединение на каждый запрос, изменения подтверждаются до ответа и отменяются при ошибке |
| З5 | маршруты `/api/trips` | список с фильтрами и сортировкой, создание с `INSERT … RETURNING`, получение, замена, удаление – с теми же ответами, что в Т4.Б1.3 |
| З6 | `GET /api/trips/summary` | сводка по покрытиям с `GROUP BY`; поездки сохраняются после «перезапуска» приложения |

Задания повышенной сложности: таблица автомобилей `cars` и внешний ключ `trips.car_id` (`sql/cars.sql`), адрес `GET /api/cars` с числом поездок и общим пробегом каждого автомобиля через `LEFT JOIN`, просмотр базы в графическом клиенте pgAdmin 4 или DBeaver.

Домашнее задание: довести задания З1–З6, решить задачи раздела 12 ноутбука; шаг прототипа – схема базы данных своего проекта не менее чем из двух связанных таблиц и хранение данных двух адресов программного интерфейса в PostgreSQL.

## Как работать

Сервер PostgreSQL запускается по варианту, который выбрал преподаватель (подробно – в `ЗАДАНИЯ.md`, задание З1).

```
cd ПР_PostgreSQL/server
python -m pip install -r requirements.txt
copy .env.example .env               # вписать свой пароль
db\db_setup.bat ваш_пароль           # вариант А; вариант Б: docker compose up -d
python -m app.init_db                # создать таблицы в рабочей базе
db\db_psql.bat -f data\archive.sql   # загрузить архив для З2
pytest                               # проверить все задания
pytest tests/test_z5.py -v           # проверить одно задание
pytest -m extra                      # задания повышенной сложности
fastapi dev app/main.py              # запустить сервер: http://127.0.0.1:8000/docs
```

## Требования

Python 3.12 или новее, библиотеки из `requirements.txt` (FastAPI 0.162.0 со стандартным набором, psycopg 3.3.8, pydantic-settings, pytest) через школьное зеркало PyPI, сервер PostgreSQL 18 (архив для Windows без установки или Docker Desktop с образом `postgres:18`), браузер Chrome или Edge, редактор VS Code. Порты 8000 и 5432 должны быть свободны. Если в школьной сети закрыт доступ к cdn.jsdelivr.net, для страницы `/docs` нужны три файла в папке `server/static/docs` (список – в README этой папки).
